# GitHub Copilot
# Definition
* GitHub Copilot is an AI-powered CODE COMPLETION Tool developed by GitHub in collaboration with OpenAI
* It assists developers by suggesting code snippets, functions and even entire blocks of code as they type, significantly enhancing productivity and code quality

# To Read
* To get autocomplete-style suggestions from an AI pair programmer as you code
* GitHub Copilot uses the GPT-3.5 Turbo model to offer coding suggestions

# Underlying Technology
* GPT Model: GitHub Copilot is powered by OpenAI's Codex model, a descendant of the GPT-3 language model, which has been specifically trained on a large dataset of code from public repositories, documentation, and other programming-related content

# Setting Context
1. Opening Files : By simply opening files relevant to your project or task in your IDE, Copilot can infer context from the content of these files
2. The #codebase directive : Developers can directly specify the context they need by using the #codebase directive in their queries
3. Context by file extension : Copilot can also infer context based on the file extension of the currently active file in the IDE
4. Context by file : You can specify a file to be used as context by typing #file. This triggers a file selector to appear, enabling you to choose a file. Additionally, it's possible to specify multiple files as context.

# Introduction to GitHub Copilot Workspace
* Copilot Workspace is an AI-driven assistant designed around tasks, supporting developers throughout their coding journey
* Integrated with GitHub, it offers contextual assistance, augmenting development skills with AI
* Accessible on every GitHub issue, it fosters collaboration and offers control to repository maintainers
* With iterative and configurable features, it empowers developers to navigate, refine, and complete tasks effectively, from inception to implementation
* Initiate an issue in Copilot Workspace : This action opens a Copilot Workspace tailored to the specific issue
* Specification : To aid in condensing complex task descriptions, such as lengthy issue discussions, Copilot Workspace initially formulates a "topic" for the task. This topic typically adopts the form of a question relevant to the codebase, serving as a basis for establishing success criteria before and after task completion
* Content Selection : In order to generate both the current and proposed specifications, as well as subsequent steps, Copilot Workspace must pinpoint the files within the codebase crucial for comprehending and executing the task
* Plan : A plan shows steps needed to edit one file and add a second one
* Implementation : This action updates the UI to show a series of queued file updates on the right side and begins generating the updated file contents one by one
* Iterating on Files : Copilot Workspace may not always get everything right, so it provides an easy way for users to iterate on the implementations file by file. You can add, remove, or edit items in the plan steps for each file, select the checkbox, and click the "Update selected files" button. This action will regenerate the contents of the selected files and update the diff view.
* Integrated Terminal : After implementing the plan, Copilot Workspace allows you to validate the changes for correctness by opening an integrated terminal where you can execute shell commands. This lets you perform actions like building, linting, and testing the changes, providing a quick and effective way to verify the task's completion status. The terminal operates within a Codespace, offering a secure sandbox with a full development environment
* Session Sharing : To facilitate sharing a workspace session with others (e.g., for an ad-hoc code review or sharing an initial implementation idea), Copilot Workspace allows users to generate shared links. These links can be shared with guests, even if they are not part of the Copilot Workspace preview
* Task Completion : Once a task is implemented, validated, and reviewed, you can complete it in various ways, depending on the specific type of task you're working on. Task type can be 1) Issue 2) Ad-hoc task 3) PR task 4) Repo task
* Session Dashboard : Copilot Workspace automatically saves your work. It also provides a session dashboard, which allows you to easily resume your work later. You can start a task from your phone and then finish up on your laptop, or vice versa.

# Copilot Shortcuts in IntelliJ IDEA
* /tests: Generate unit tests for your code. Automatically generates unit tests based on the current code context, helping to ensure code quality and coverage.
* /simplify: Simplify the selected code. Analyzes the selected code and provides a simplified version, making it more readable and maintainable
* /fix: Fix problems and compile errors in your code. Detects and resolves common problems and compile errors in your code, saving time during debugging.
* /explain: Explain how the selected code works. Provides a detailed explanation of the selected code, useful for understanding complex logic or unfamiliar codebases
* /doc: Document the current selection of code. Generates documentation for the selected code, improving code documentation practices.
* /feedback: Steps to provide feedback to the Copilot team. Guides you on how to submit feedback to the GitHub Copilot team, helping improve the tool
* /help: Get help on how to use Copilot chat and other features. Offers guidance on using Copilot chat and accessing other Copilot features, ensuring you get the most out of the tool

# Creating a pull request summary with GitHub Copilot
* GitHub Copilot offers an AI-powered feature to generate descriptions for pull requests
* This tool creates a summary of changes, identifies impacted files, and highlights key areas for reviewers
* Copilot generates summaries in response to user requests, scanning the pull request and provides a paragraph overview of the changes and a bulleted list of key changes linked to the respective lines of code
* This feature can be initiated during pull request creation, by editing the pull request description, or by commenting in the pull request thread

# Benefits of Using Pull Request Summaries
* Copilot pull request summaries aim to streamline the process of adding context to pull requests
* Copilot enhances developer productivity by reducing the time required to draft pull request descriptions
* Copilot provides comprehensive context, making it easier for reviewers to understand the changes

# Improving Performance of Pull Request Summaries
* Performance = Accuracy of Copilot-generated summaries
* While Copilot is a powerful tool, it should supplement rather than replace the manual addition of context by the author
* Authors should continue to review and verify the accuracy of Copilot-generated summaries
* Feedback on summaries can be provided directly through the UI to help improve the feature

# Limitations of Pull Request Summaries
1. Limited Scope : Summaries may omit changes in pull requests affecting more than 30 files.
2. Processing Time : Summaries typically take 40 seconds but can take up to a couple of minutes
3. Inaccurate response : The summaries may not always be accurate and can include errors or "hallucinations," necessitating manual review and editing.
4. Manula updates : Summaries are not automatically updated with changes to the pull request. Users need to manually regenerate summaries as needed.


# Regenerating Summaries
* If updates or changes are made to a pull request, users can manually request a new summary
* It is crucial to review regenerated summaries for accuracy, as they carry the same risks as initial summaries

# Pull Request Summary
* Copilot pull request summaries are a valuable tool for enhancing the efficiency of drafting pull request descriptions
* By understanding its capabilities and limitations, users can effectively leverage this feature to improve their workflow and ensure that pull requests are thoroughly and accurately documented

# How to use this feature:
1. Step 1 : On GitHub.com, create a pull request or navigate to an existing pull request.
2. Step 2 : Navigate to the text field where you want to add the pull request summary.
3. Step 3 : In the header of the text field, select , then click Summary
4. Step 4 : Wait for GitHub Copilot to produce the summary, then check over the results carefully.
5. Step 5 : Add any additional context that will help people viewing your pull request.
6. Step 6 : When you're happy with the description, click Create pull request on a new pull request, or Update comment if you're editing an existing description
